## 1. 背景と目的

ラーメン屋は運営形式も種類も多様で、一軒ごとの個性が強い。「あの店うまかったな」「最近どのくらい食べているんだろう」という記憶をさかのぼる行為を支援することを目的とする。

対象はラーメンを食べる人全般で、頻度は問わない。記録を「つける」ことより「振り返る」ことに軸足を置き、入力項目を最小限に絞って継続の障壁を下げる。

## 2. 設計方針

本アプリは以下の方針を前提とする。この前提が機能要件・非機能要件の全体を規定する。

1. **バックエンドを持たない。** 記録は端末内にのみ保存し、サーバーへ送信しない。
2. **単一端末での利用を前提とする。** 端末間同期は行わず、データ移動は JSON ファイルの手動受け渡しで代替する。
3. **インストール可能であること。** iPhone のホーム画面から、ネイティブアプリと同等の起動体験で利用できる。
4. **オフラインで完結すること。** 外部ホストへのリクエストを持たず、機内モードでも全機能が動作する。

## 3. スコープ

### 3.1 対象

- ラーメン店の来訪記録の作成・閲覧・削除
- 最終来訪日からの経過日数の可視化
- 記録の JSON エクスポート／インポート
- ホーム画面へのインストールとオフライン動作

### 3.2 対象外

以下は意図的に実装しない。理由を併記する。

| 項目 | 対象外とする理由 |
| --- | --- |
| ユーザー認証 | サーバーを持たず、データが端末内に閉じているため不要 |
| サーバー側データ保存 | 設計方針 1 に反する |
| 複数端末間の自動同期 | 設計方針 2 に反する。エクスポート／インポートで代替 |
| 店名・日付・評価の編集 | 現バージョンでは未提供。削除して再登録で代替。感想のみ後から編集できる（FR-14） |
| 店舗検索・地図連携 | 外部 API 依存が生じ、設計方針 4 に反する |

## 4. 用語定義

| 用語 | 定義 |
| --- | --- |
| 記録 | 1 回の来訪を表すデータ。店名・日付・評価の 3 項目を持つ |
| 履歴 | 記録の集合。本アプリが保持する唯一のデータ |
| 経過日数 | 本日から、履歴中で最も新しい記録の日付を引いた日数 |
| 状態絵文字 | 経過日数に応じて表示される絵文字。ラーメン欠乏度を表す |
| 旧形式データ | 本バージョン以前に保存された、`id` を持たず評価が文字列のデータ |

## 5. 機能要件

| ID | 機能 | 概要 |
| --- | --- | --- |
| FR-01 | 記録の追加 | 店名・日付・評価を入力して記録を 1 件登録する |
| FR-02 | 記録の一覧表示 | 履歴を新しい順に一覧表示する |
| FR-03 | 記録の詳細表示 | 一覧の 1 件を選択して詳細を表示する |
| FR-04 | 記録の削除 | 確認のうえ記録を 1 件削除する |
| FR-05 | 経過日数の表示 | 最終来訪からの経過日数を表示する |
| FR-06 | 状態絵文字の表示 | 経過日数に応じた絵文字と説明を表示する |
| FR-07 | エクスポート | 履歴を JSON ファイルとして書き出す |
| FR-08 | インポート | JSON ファイルを読み込んで履歴を置き換える |
| FR-09 | データの永続化 | 履歴を端末内に保存し、再起動後も保持する |
| FR-10 | 旧形式データの移行 | 旧形式で保存されたデータを現行形式へ自動変換する |
| FR-11 | インストール | ホーム画面に追加して全画面で起動する |
| FR-12 | オフライン動作 | ネットワーク不通時も全機能が動作する |
| FR-13 | 自動更新 | 新しい版が公開された際、再インストールなしで更新する |
| FR-14 | 感想の追記・編集 | 登録済みの記録に感想を書き足す、または書き換える |

### FR-01 記録の追加

| 項目 | 内容 |
| --- | --- |
| 入力 | 店名（自由入力）、日付（日付選択）、評価（★ 0.5〜5.0、0.5 刻み）、感想（自由入力・任意） |
| 初期値 | 店名は空、日付は本日、評価は 2.5、感想は空 |
| 処理 | 入力値を検証し、履歴の末尾に 1 件追加して保存する |
| 出力 | ダイアログを閉じ、一覧・経過日数・状態絵文字を即時更新する |
| 例外 | 店名が空白のみ、日付が未選択、評価が未設定のいずれかの場合は登録せず「店名・日付・評価を入力してください」を表示する |

店名と感想の前後の空白は除去して保存する。感想は任意項目で、未記入なら記録に持たせない。追加後、入力欄は初期値に戻る。

### FR-02 記録の一覧表示

日付の降順（新しい記録が上）で表示する。1 件あたり店名・日付・評価を表示する。

履歴が 0 件のときは一覧を表示せず、「「追加」ボタンから最初の一杯を記録しよう！」を表示する。

店名が表示幅を超える場合は末尾を省略記号で切り詰め、横スクロールを発生させない。

### FR-03 記録の詳細表示

一覧の記録本体を選択するとダイアログを開き、店名・日付・評価・感想を表示する。閉じる操作でダイアログを閉じる。

感想が未記入の場合は「まだ書いていません」を表示する。感想の改行は入力どおりに表示する。

詳細表示中にその記録が削除された場合、ダイアログは自動的に閉じる。

### FR-04 記録の削除

削除操作時に「「（店名）」の記録を削除しますか？」を確認する。承認された場合のみ削除し、保存する。取り消し機能は提供しない。

### FR-05 経過日数の表示

画面最上部に、履歴の状態に応じて次の文言を表示する。

| 条件 | 表示 |
| --- | --- |
| 履歴が 0 件 | まだ記録がありません |
| 経過日数が 0 以下 | 今日ラーメンを食べました |
| それ以外 | ラーメンに行ってから **N日** が経過しました |

経過日数は日付単位で算出し、時刻は考慮しない。未来日付が記録された場合は 0 以下として扱う。

### FR-06 状態絵文字の表示

経過日数に応じて絵文字を表示する。長押しまたはホバーで説明を表示する。

| 経過日数 | 絵文字 | 説明 |
| --- | --- | --- |
| 履歴なし | ❓ | 履歴が見つかりません |
| 3 日未満 | 🍜 | 最近食べたね（余裕） |
| 3 日以上 7 日未満 | 🙂 | まだ大丈夫 |
| 7 日以上 14 日未満 | 😢 | そろそろ行っておいたほうが良いかも |
| 14 日以上 | 😭 | 禁断症状（至急ラーメン） |

### FR-07 エクスポート

履歴を `ramen_history.json` として書き出す。実行環境に応じて出力方法を切り替える。

| 環境 | 動作 |
| --- | --- |
| ファイル共有に対応する環境（iOS 等） | OS の共有シートを開き、保存先をユーザーが選択する |
| 対応しない環境 | ファイルをダウンロードする |

共有シートをユーザーが閉じた場合は何もしない。履歴が 0 件のときは「エクスポートするデータがありません」を表示する。

> iOS のホーム画面アプリではダウンロード操作が機能しないため、共有シート経由の出力が唯一のバックアップ手段となる。

### FR-08 インポート

JSON ファイルを選択して履歴を置き換える。

| 段階 | 動作 |
| --- | --- |
| 検証 | 記録の配列として解釈できるか確認する |
| 確認 | 「現在の記録をすべて置き換えて、N件を読み込みます。よろしいですか？」を表示する |
| 実行 | 承認された場合のみ置き換え、「インポートが完了しました」を表示する |

形式が不正な場合は「不正なファイル形式です」、読み込みに失敗した場合は「ファイルの読み込みに失敗しました」を表示し、既存の履歴は変更しない。

同じファイルを続けて選択し直せること。

### FR-09 データの永続化

履歴の変更は即時に端末内へ保存する。保存に失敗した場合は、容量不足の可能性とエクスポートの実施を促すメッセージを表示する。

### FR-10 旧形式データの移行

起動時に保存データを検査し、旧形式であれば現行形式へ変換して書き戻す。移行はユーザー操作を要さず、記録の内容は保持される。

| 旧形式 | 現行形式 |
| --- | --- |
| 識別子を持たない | 一意な識別子を付与する |
| 評価が文字列（例 `"4.5"`） | 数値（例 `4.5`）に変換する |

### FR-11 インストール

iPhone の Safari から「ホーム画面に追加」でインストールできる。起動時はブラウザの UI を表示せず全画面で動作し、画面の向きは縦に固定する。

### FR-12 オフライン動作

初回読み込み後は、ネットワーク不通時も全機能が動作する。外部ホストへのリクエストを一切持たない。

### FR-13 自動更新

新しい版が公開された場合、次回起動時に自動で更新する。ユーザーによる再インストールを要しない。

### FR-14 感想の追記・編集

詳細表示から感想を書き足す、または書き換える。感想を持たない記録にも後から追記できる。

| 項目 | 内容 |
| --- | --- |
| 入力 | 感想（自由入力・複数行） |
| 処理 | 前後の空白を除去して保存する。空にした場合は記録から感想を取り除く |
| 出力 | 表示状態に戻り、一覧と詳細に即時反映する |
| 取り消し | 編集中の内容を破棄して元の感想に戻す |

編集中は背景をタップしてもダイアログを閉じない。書きかけの内容を誤って失わないようにするためである。

店名・日付・評価の編集は提供しない。

## 6. 画面仕様

### 6.1 画面一覧

| 画面 | 種別 | 遷移元 |
| --- | --- | --- |
| メイン画面 | 常時表示 | — |
| 新規記録ダイアログ | モーダル | メイン画面の「追加」 |
| 詳細ダイアログ | モーダル | 一覧の記録本体 |

画面遷移は持たず、すべてメイン画面上のモーダルとして表現する。

### 6.2 メイン画面

上から順に次の要素を配置する。

| 要素 | 内容 |
| --- | --- |
| 経過日数表示 | FR-05 の文言と FR-06 の絵文字 |
| 操作列 | 「追加」「読み込み」「書き出し」の 3 ボタン |
| 履歴一覧 | FR-02 の一覧、または空状態メッセージ |

### 6.3 新規記録ダイアログ

| 要素 | 種別 | 初期値 |
| --- | --- | --- |
| 店名 | テキスト入力 | 空 |
| 日付 | 日付選択 | 本日 |
| 評価 | ★ 選択（0.5 刻み） | 2.5 |
| 感想 | 複数行テキスト入力（任意） | 空 |
| 保存 | ボタン | — |
| 閉じる | ボタン | — |

### 6.4 詳細ダイアログ

店名を見出しとし、日付・評価・感想を表示する。

| 状態 | 表示 | 操作 |
| --- | --- | --- |
| 表示 | 感想（未記入なら「まだ書いていません」） | 「感想を書く」または「感想を編集」／「閉じる」 |
| 編集 | 感想の入力欄 | 「保存」／「取り消し」 |

操作ボタンの文言は、感想が未記入なら「感想を書く」、記入済みなら「感想を編集」とする。

## 7. データ仕様

エクスポート／インポートで扱う JSON の外部仕様を定義する。

記録の配列とする。各要素は次のフィールドを持つ。

| フィールド | 型 | 必須 | 内容 |
| --- | --- | --- | --- |
| `id` | 文字列 | 任意 | 記録の一意な識別子。欠落時は読み込み時に自動採番する |
| `shop` | 文字列 | 必須 | 店名 |
| `date` | 文字列 | 必須 | 来訪日。`YYYY-MM-DD` 形式 |
| `rating` | 数値 | 必須 | 評価。0.5〜5.0。文字列で与えられた場合は数値に変換する |
| `memo` | 文字列 | 任意 | 感想。未記入の記録では省略される |

```json
[
  {
    "id": "4036fdb3-4016-4fea-9e29-d7b1cbebed78",
    "shop": "麺屋 いろは",
    "date": "2026-08-14",
    "rating": 4.5,
    "memo": "濃厚な魚介豚骨。
味玉が半熟で最高だった。"
  }
]
```

配列でない、または 1 件でも `shop` / `date` / `rating` を満たさない要素を含む場合、そのファイル全体を不正として扱う。`memo` は任意項目のため、欠けていても不正としない。

感想の追加によるファイル形式の変更はない。感想対応前に書き出したファイルもそのまま読み込める。

## 8. 非機能要件

| ID | 分類 | 要件 |
| --- | --- | --- |
| NFR-01 | 対応環境 | iOS 16 以降の Safari を主対象とする。Chrome / Edge / Firefox の最新版でも動作する |
| NFR-02 | 画面幅 | 375px 幅で横スクロールを発生させない |
| NFR-03 | 性能 | 初回読み込み後はネットワークアクセスなしで起動する |
| NFR-04 | オフライン | 全機能がオフラインで動作する。外部ホストへのリクエストを持たない |
| NFR-05 | プライバシー | 記録を端末外へ送信しない。認証情報・個人識別情報を扱わない |
| NFR-06 | データ保全 | 保存失敗時にユーザーへ通知し、バックアップ手段を案内する |
| NFR-07 | アクセシビリティ | 操作要素に用途を説明するラベルを付与する。評価は数値としても読み上げ可能とする |
| NFR-08 | 保守性 | 型検査と静的解析を通過することをビルドの前提とする |

## 9. 制約事項と既知の制限

| 項目 | 内容 | 緩和策 |
| --- | --- | --- |
| 保存容量 | 端末内保存の上限は概ね 5MB | 現行の項目構成では実用上問題にならない。写真機能の追加時は保存方式の変更が必要 |
| データ揮発 | iOS はストレージ逼迫時に保存データを削除することがある | 定期的なエクスポートを readme で案内する |
| インストール手段 | iPhone では Safari からのみホーム画面に追加できる | 手順を readme に明記する |
| 公開範囲 | 公開 URL は認証なしで誰でも開ける | 記録は端末内にのみ存在するため、第三者が開いても空のアプリが表示されるのみ |
| 端末間の共有 | 自動同期を持たない | JSON ファイルの受け渡しで代替する。友人へのファイル共有という利用方法も生まれる |
| 記録の編集 | 未提供 | 削除して再登録する |

## 10. 今後の拡張予定

| 機能 | 内容 | 備考 |
| --- | --- | --- |
| 記録項目の拡充 | トッピング、系統、金額 | 感想と同様に詳細ダイアログで編集可能にする |
| 写真の添付 | 来訪時の写真を記録に添付する | 保存容量の制約により、保存方式の変更を伴う |
| 並び替え・絞り込み | 評価順、期間指定など | 記録が識別子を持つため、実装時に既存機能への影響はない |
| 記録の編集 | 登録済み記録の修正 | — |
